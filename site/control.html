    04
    Reaching the real robot
    Details
    
      
    This public page is served over https. A browser does not let an https page call http or ws addresses on
        your network, and no web page can open the board's TCP port. So this page cannot reach a robot, and it does
        not pretend to. The same page is served by a small server in the repository that sits next to the robot's
        socket, as the sketchbot's Studio is served from its UNO Q. Run one of these from a checkout and open the
        address it prints:
    
      
    Rehearsal, no hardware (two terminals):
    
      
    python scripts/virtual_robot.py
    
      
    python app_lab/microduck_agent/control_server.py --allow-motion
    
      
    On the UNO Q, next to the agent (see Flash):
    
      
    python3 app_lab/microduck_agent/control_server.py --bind 0.0.0.0 --allow-motion
    
      
    Or on your computer, as a bridge to the board:
    
      
    python app_lab/microduck_agent/control_server.py --robot unoq.local:8766 --real --allow-motion
    
      
      
        
    • Motion needs --allow-motion on the server, an armed session after the pre-flight checklist, and a held enable control for every command.
      • 
        
    • Commands are rate limited to 20 a second in the page and refused faster than one per 30 ms by the server. Nothing is queued.
      • 
        
    • Every target passes the firmware's soft limits, its 120 deg/s speed limit and its 500 ms watchdog.
      • 
        
    • Releasing the enable control, Stop, Esc, a lost controller, a hidden tab, a lost window focus or a dropped connection sends the stop sequence; after that nothing is sent and the watchdog holds the pose.
      • 
        
    • Stop does not cut servo power. Keep a hand on the supply switch.
      • 
        
    • The server has no login. Use a trusted network and never forward its port to the Internet.
